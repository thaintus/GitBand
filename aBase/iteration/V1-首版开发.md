## 背景

基于《GitBind设计文档.md》与《TECH_ARCHITECTURE.md》（现位于 `aBase/doc/`），搭建 Git 仓库账号绑定管理工具的首个可运行版本。目标是先跑通核心骨架与数据流，第二版再补齐英文与语言切换。

## 分层实现要点

### Domain
- 实体：`Account`、`Project`、`Binding`、`RepositorySnapshot`
- 枚举：`Platform`、`AuthenticationType`、`BindingStatus`、`RemoteProtocol`、`GlobalModeState`
- `EffectiveAccountResolver`：统一决策「Global Mode > Project Binding > Default Account」
- `DomainError` / `Result<T>`：错误模型与业务结果类型
- `AccountFactory`：创建账号并遵守 Alias 默认值规则

### Application
- 仓储接口：`IAccountRepository`、`IProjectRepository`、`IBindingRepository`、`ISettingsRepository`、`IRepositorySnapshotRepository`
- 端口接口：`ICommandExecutor`、`ILocalizationService`、`IPathNormalizer`、`IApplicationDataPath`、`IShellService`、`IGitService`、`IGitConfigApplier`、`ISecretStore`、`IGitLocator`、`ISshLocator`
- 应用服务：`AccountService`、`ProjectService`、`BindingService`、`GlobalModeService`、`SecretService`
- 依赖注入注册：`DependencyInjection.cs`

### Infrastructure
- `Schema.cs`：SQLite 建表（accounts/projects/bindings/repository_snapshots/settings/operation_logs）
- 仓储实现：AccountRepository、ProjectRepository、BindingRepository、SettingsRepository、RepositorySnapshotRepository
- `GitService`：仓库校验、Root/GitDir/Origin/Branch 读取、Remote 解析、ls-remote 测试
- `GitLocator`/`SshLocator`：定位系统 Git/SSH
- `CommandExecutor`：参数数组执行外部命令
- `DependencyInjection.cs` + `DatabaseInitializer`：启动时初始化 Schema

### Platform（Windows）
- `WindowsPathNormalizer`：大小写不敏感的路径规范化
- `WindowsApplicationDataPath`：`%LOCALAPPDATA%\GitBinder\` 下各子目录
- `WindowsDpapiSecretStore`：DPAPI CurrentUser 加密，密文落盘
- `WindowsShellService`：打开目录/终端

### Desktop
- `CompositionRoot`：DI 容器构建 + 数据库初始化
- `LocalizationService` + `StringsZhCn` / `StringsEnUs`：i18n 架构（V1 仅中文，英文为占位）
- ViewModel：Main / Dashboard / Accounts / Projects / Bindings / Settings
- View：MainWindow（侧边导航 + Global Mode 横幅）+ 五个页面 UserControl

### CredentialHelper
- 输出程序集名 `gitbinder-credential`
- 实现 Git Credential Protocol 的 `get` 操作，从 Secret Store 读取 HTTPS 凭据
- 支持通过 `GITBINDER_ACCOUNT_ID` 环境变量指定账号，否则按 host 匹配

# V2 本地化与语言切换（2026-08-23）

## 目标

实现英文界面与中英文动态切换，满足 `TECH_ARCHITECTURE.md` §18-§31 的 i18n 要求。

## 实现方案

采用「索引器绑定 + INotifyPropertyChanged」实现 XAML 动态本地化：

- `LocalizationService` 实现 `INotifyPropertyChanged`，暴露 `this[string key]` 索引器，切换语言后触发 `PropertyChanged("Item[]")` 通知所有绑定刷新。
- 新增 `LocExtension`（`src/Desktop/Localization/LocExtension.cs`），XAML 中以 `{loc:Loc Key}` 形式绑定文案，OneWay 动态刷新。
- `LocalizationService.Instance` 静态单例，供 `LocExtension` 提供 `Binding.Source`。

   - `LocalizationService` 增加索引器 + `INotifyPropertyChanged` + 静态 `Instance`。

   - 切换后持久化到 `settings.language`，启动时 `CompositionRoot` 读取并应用。

3. **View 去硬编码**：

## 账号编辑页三块重构

按用户反馈将账号编辑页重构为三块卡片式设计，去掉冗余字段：

1. **① Git 信息**：提交姓名、提交邮箱、别名（默认等于提交姓名，可修改）、平台。
2. **② HTTPS 账密**：账号、密码（留空不启用 HTTPS 认证）。
3. **③ SSH 私钥**：上传私钥（留空不启用 SSH 认证）。

- **认证方式自动推断**：填了账密→HTTPS；上传了私钥→SSH；都有→Both；都空→None。无需手选"类型"。

# 项目绑定生效与 Git 地址维护（2026-08-24）

## 背景

补齐项目页两项实际维护能力：

1. 非全局模式下改绑账号后，界面不能在仓库本地 Git 配置写入失败时仍显示“已保存”。
2. 已登记仓库可能从云效迁移至 GitHub 等其他平台，需要直接维护本地 `origin` 地址，而非移除后重新登记项目。

## 变更内容

### 非全局模式改绑

- `GitConfigApplier` 通过 `IGitLocator` 使用已定位的 Git 可执行文件写入本地配置。
- 切换账号时以 `--replace-all` 覆盖 `user.name`、`user.email` 与 `core.sshCommand`；账号未填写的可选字段以 `--unset-all` 清除旧值，避免遗留前一账号的邮箱或 SSH 配置。
- 本地 Git 配置写入失败会抛出并由 `BindingService.BindAsync` 转为 `BINDING_APPLY_FAILED`；此时不更新绑定记录，保留原绑定，避免“绑定数据已改、仓库身份未改”的不一致。
- 新增中英文错误文案，并新增 Fake 场景测试：改绑写入失败时仍保持原账号绑定。

### 修改项目 Git 地址

- 项目卡片新增“修改地址”入口，显示当前 `origin`，可展开编辑、保存或取消。
- `ProjectService.UpdateOriginUrlAsync` 先校验本地仓库，再调用 Git 服务更新地址；仅改本地 Git 配置，不联网、不拉取、不推送。
- `GitService.SetOriginUrlAsync`：已有 `origin` 时执行 `git remote set-url origin <url>`；不存在时执行 `git remote add origin <url>`。
- 成功后同步保存 `OriginUrl`、`RemoteProtocol`、`RemoteHost` 和更新时间。地址变更不会自动改绑账号，用户可按新平台在同一卡片重新选择并保存绑定账号。
- 禁止保存携带 HTTPS 用户名、密码或 Token 的 URL；对旧数据中可能存在的 HTTPS userinfo，项目列表和编辑框会隐藏该部分。

## 跨平台绑定的认证隔离（2026-08-24）

### 背景与规则

- `codeup.aliyun.com` 项目改绑为 `github.com` 账号是允许的：绑定描述的是当前仓库应使用哪个本地提交身份和认证账号，不以 Remote Host 限制账号所属平台。
- 先前问题在于：账号没有指定 SSH 私钥时，程序清除了 `core.sshCommand`，Git 随即回退到系统 SSH Agent 或默认云效 Key，出现“GitHub 身份 + 云效远程认证”仍可推送的错配。
- 现在 SSH Remote 始终写入当前选中账号的私钥命令；若该账号未提供 SSH 私钥，则写入 Windows 空配置/空身份文件（`-F NUL -i NUL`）并禁用 Agent、交互认证的失败关闭命令，因此不得借用系统其他 Key。
- HTTPS/HTTP Remote 会以本仓库空的 `credential.helper` 重置继承 Helper 链；仅当选中账号有 HTTPS Secret 时才追加携带 `--account-id` 的 `gitbinder-credential.exe` 绝对路径。Secret、Token 与密码均不写入 Git 配置。
- 连接测试会先按当前实际生效账号刷新上述本地认证配置。全局模式除重写已登记仓库外，也以相同的无回退 SSH/HTTPS 规则覆盖全局 Git 配置；关闭时恢复进入全局模式前快照。
- 修复升级后的旧绑定遗漏：应用启动时即使全局模式关闭，也会重新应用所有已登记绑定，确保旧云效项目改绑 GitHub 后同样写入无回退 SSH/HTTPS 配置，无需用户再次保存绑定。

### 变更与涉及文件

- `src/GitBinder.Application/Bindings/BindingService.cs`：移除 Remote Host 拦截和状态，改为按 Remote 协议应用无回退 SSH/HTTPS 配置；测试沿用全局模式下解析出的实际账号。
- `src/GitBinder.Application/Git/IGitConfigApplier.cs`、`src/GitBinder.Infrastructure/Git/GitConfigApplier.cs`：新增账号固定的 Credential Helper 配置；全局快照与恢复涵盖 `credential.helper`。
- `src/GitBinder.CredentialHelper/Program.cs`：解析 `--account-id` 参数并校验账号启用状态和 HTTPS 认证类型，保留环境变量/Host 解析仅作旧配置兼容。
- `src/GitBinder.Application/GlobalMode/IGlobalGitConfigApplier.cs`、`src/GitBinder.Domain/Bindings/BindingStatus.cs`、本地化文件：移除已废弃的 Remote Host 不匹配状态与文案。
